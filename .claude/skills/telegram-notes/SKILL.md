## Telegram (optional push + voting)

- Kill switch: `config.TELEGRAM_ENABLED` (default `False`). When `True`, `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` must be set in `.env` — both modules load them via their own `load_dotenv()` call (not coupled to `env.py`'s import order).
- `telegram_notifier.send_listing_alert(post_url, fields, score)` fires once a batch of matches is actually written to the sheet (both `_scan_group_page`'s batched flush and `reparse_rejected_posts()`'s per-row append) — never on a dry run, matching the rule that dry runs commit nothing anywhere. Wrapped in try/except at every call site: a Telegram outage prints a `WARNING` and never breaks the scrape — the match is already safely in the sheet regardless. The alert isn't lost: an added post with no stored `telegram_message_id` is "owed", and the next live `run_scraper()` re-sends it (`_resend_owed_alerts()` in `sources/fb_scraper.py`, right after the run-started alert) rebuilt from its sheet row via `sheets._fields_from_sheet_row()`. Only within `ALERT_RETRY_MAX_AGE_HOURS` (48); a listing no longer in the sheet is skipped.
- The message carries a `telegram_notifier.build_listing_keyboard(up, down, group_id, post_id)` keyboard: the ⭐/🗑 vote row plus a "🔗 פתח פוסט" URL-button row — but **new listing messages no longer carry the vote buttons at all** (only the link, via `build_link_keyboard(post_url)` — the listing's own URL, so a Yad2 listing (`sources/mail_source.py`) links to its Yad2 page; the 0-10 rating rows were dropped earlier too). The link row also gets a "🗺 פתח במפות" button (`_maps_url()`: a `google.com/maps/search/?api=1&query=<address, ישראל>` https link — Telegram URL buttons can't carry `geo:` URIs, so this is what hands off to the Maps app on a phone) **only when the street is known**: stored `address_confidence == "high"` (street word or house number), else the same `_classify_address_confidence` on the text; city-only, neighborhood/landmark and missing addresses get no button, deliberately strict. A third "💬 וואטסאפ" button (`_whatsapp_url()`, 2026-11-07, idea from thehapyone/Apartment-Bot's auto-apply) opens a `wa.me/972…` chat with the poster's first **mobile** number (`core.normalize._first_mobile_phone`, 05X only) and a pre-filled Hebrew opener naming the address — one tap to contact, while the bot itself stays read-only on Facebook. The phone is attached as `fields["contact_phone"]` only on the live path (`process_candidate_listing`); alerts rebuilt from a sheet row (re-sent owed alerts, `--backfill-ratings`) carry no phone and get no button. `build_listing_keyboard` survives solely so `bot_listener.py` can refresh messages sent *before* the removal; the vote/rating sheet actions below only fire on taps on those old messages. The vote buttons are built off `callback_data` = `"{up|down}:{group_id}:{post_id}"` (the FB group+post id pair, reconstructable back into the canonical post URL — see `_canonical_post_url`) rather than the full URL, to stay under Telegram's 64-byte callback_data limit. `build_listing_keyboard()` is the single source for this layout — both the initial `send_listing_alert()` and every `bot_listener.py` tally-refresh reuse it, so a vote tap can't wipe the link row off the message or vice versa.
- **Message format** (`_format_listing_message()`): Telegram **HTML** parse mode (`parse_mode: "HTML"`, link preview off — the post link is the URL button, not text). Every dynamic value goes through `_escape()` (`html.escape`) because address/warning/entry-date text is scraped Facebook text via an LLM: an unescaped `<`/`&` makes Telegram reject the whole message with a 400, silently losing the alert. A line or field with no data is omitted — no `?` placeholders, matching the unknown-is-blank convention; a non-numeric `distance_text` placeholder is skipped; floor 0 renders as `קרקע`. Under the headline, `📰 מקור: פייסבוק`/`יד2` (`_source_label()`, from the listing URL's domain; no line for any other URL). The headline carries a 🟢/🟡/🔴 tier (`TELEGRAM_SCORE_GOOD`/`TELEGRAM_SCORE_OK`, set from the sheet's score tertiles 2026-10-15) and the line `עלות חודשית כוללת` is computed in the formatter via `scoring.compute_total_monthly_cost(fields)`, so it works for both the live path and `--backfill-ratings` (fields rebuilt from a sheet row).
- **Chat commands** (`integrations/telegram_commands.py`, 2026-11-12): `bot_listener.py` passes every `message` update to `handle_message(message, TELEGRAM_CHAT_ID, send)` and calls `setMyCommands` from `COMMANDS` at startup (the `/` menu). Obeyed only from `TELEGRAM_CHAT_ID`, only the fixed names in `COMMANDS` (`/scan@BotName` group form accepted), never with arguments — message text never reaches a command line. A message older than `_STALE_COMMAND_S` (5 min) is dropped: `getUpdates` replays what arrived while the listener was down. `/scan` → `subprocess.Popen([python, -u, apartment_bot.py])` (no window, `PYTHONIOENCODING=utf-8`: with stdout not a console, Windows Python would print Hebrew/₪ as cp1252 and crash), refused while a scan runs — our process, or a `runs` row `running` started under `_RUNNING_ROW_MAX_AGE` (2h; older = killed without closing). A watcher thread reports an exit code other than 0/2 (those send their own run-finished message), e.g. a lost login. `/stop` kills only a scan started from the chat, as a tree (`taskkill /T /F` — Playwright's driver and Chromium would otherwise keep `chrome_profile` locked), and marks the `running` rows `stopped`. `/stats` `/doctor` `/sync_groups` run the CLI on a thread (`_CLI_TIMEOUT_S` 300) and reply with its output in `<pre>`, HTML-escaped, cut to `_OUTPUT_LIMIT`.
- `bot_listener.py` is a **separate long-running process** (`python bot_listener.py`, not invoked by the scraper) that long-polls `getUpdates` and branches on the `callback_data` prefix:
  - `up`/`down` — records the vote via `storage.record_vote()` (upsert — a voter's latest tap wins), edits the button labels to show the running tally (`⭐ מעניין (N)` / `🗑 לא רלוונטי (M)`), and drives the sheet actions below.
  - `rate` — records a 0-10 score via `storage.record_rating()` (same upsert rule) and just acknowledges with an `answerCallbackQuery` toast (`"ניקוד N/10 נשמר"`). No sheet side effect at all — pure data collection, meant as the eventual training set for regressing `scoring.compute_fit_score()`'s weights against real human judgment instead of the current guessed ones. Read back via `storage.get_ratings_with_listing_data()`, which joins `ratings` against `posts` (price/rooms/distance/`parsed_json`) so a rating comes with the listing's actual attributes attached.
  - Resumes from `storage.get_telegram_offset()` after a restart either way, so it never replays old votes or ratings.
- `apartment_bot.py --backfill-ratings` pushes every row currently in the sheet through `send_listing_alert()` again (1.2s pacing between sends, well under Telegram's per-chat rate limit) so members can retroactively rate apartments that were added before the rating keyboard existed — the fastest way to build up a non-trivial training set without waiting for new matches to trickle in. No browser, no Maps/Gemini calls; reuses the same row→fields reconstruction as `--recompute-scores` (see below), so it inherits the same lat/lon gap (neutral direction-score component, doesn't affect the message itself).
- Storage: `posts.telegram_chat_id`/`telegram_message_id` (which message to edit), `votes` table (`url`, `voter_id`, `voter_name`, `vote`, `voted_at`, PK on `url`+`voter_id`), `ratings` table (`url`, `voter_id`, `voter_name`, `score`, `rated_at`, PK on `url`+`voter_id`), `telegram_state` (single-row `update_offset` for the listener's poll cursor).
- `doctor.py --alert` uses `telegram_notifier.send_failure_alert()` to DM a summary when any health check FAILs — the only other caller of `telegram_notifier`.
- **Vote-driven sheet actions** (`bot_listener.py`, on every `callback_query`): reads/writes the sheet directly (its own `_open_sheet()`/gspread client, separate from `integrations/sheets.py`'s), finding the listing's row by URL via `sheet.find(url, in_column=1)` — **this returns `None` on no match in the installed gspread version, it does not raise**, so `_find_row()` checks for `None` explicitly before dereferencing; a bare try/except around `.find()` alone would still crash.
  - `config.VOTES_TO_REMOVE` (default 2) down-votes → the row is deleted from the sheet outright (`sheet.delete_rows`); the DB `posts` row/verdict is left untouched, so `_known_added_listing_keys()` still treats it as a known listing and a later crosspost of the same apartment is silently skipped as `duplicate_listing` rather than resurfacing — deliberate, matches "the group already said no."
  - Every up-vote bumps the row's `ציון התאמה` (fit score) cell by `config.SCORE_VOTE_BOOST` (default 10), clamped to 100 (`_boost_score()`) — a direct sheet edit, not a recompute of `scoring.compute_fit_score()`.
  - `config.VOTES_TO_HIGHLIGHT` (default 2) up-votes → `telegram_notifier.send_highlight_alert()` sends a distinct "🔥" message (HTML, vote-less, with only the 🔗 link button) built from that row's own cells (score/price/rooms/total cost/distance/address/entry date/floor/elevator), not from `_evaluate_post_data()`'s `fields` dict (bot_listener.py never sees that — it only has the callback's group/post id and whatever's already in the sheet).
  - No column for the vote tally exists in the sheet (removed by design — score bump + row removal are the only sheet-visible effects of a vote); the running ⭐/🗑 count only ever appears on the Telegram message's button labels.
- **Run-start/run-finish alerts** (`run_scraper()`, gated on `live and TELEGRAM_ENABLED` — never on a dry run; HTML, both wrapped in try/except so a Telegram failure only prints a `WARNING`). Built by the pure, unit-tested `_format_run_started()` / `_format_run_finished()` (2026-11-11). Start (`fb_scraper._run_started_info()`): time, active group count and how many were never scanned (deeper first scan), whether Yad2 emails are read, the search criteria from config, and the previous successful live run (how long ago, how many added — `storage.get_last_successful_live_run()`). Finish: duration; each new listing (rooms · price · distance · address linked to the post, at most `_RUN_FINISHED_MAX_LISTINGS`) with a Facebook/Yad2 split; the console summary numbers; rejections by reason, most common first (`_REJECTION_LABELS`); posts per model; Maps calls only when nonzero; active groups whose status is `not_member`; checkpoints; log errors/warnings. The per-run detail comes from `storage.get_run_activity(run_started_at)` — posts whose `last_processed` is after the run began. **Live progress bar**: `send_run_started()` returns the message id; `run_scraper()` hands it to `fb_scraper._ScanProgress`, which edits the message (`update_run_progress()`, `editMessageText`) with `format_run_progress()` — `⏳ ▓▓▓▓░░░░ 23/54 קבוצות · 4 נוספו · עוד ~15 דק'`, ending `✔️ … הסיכום בהודעה הבאה` — after each group and every `PROGRESS_TICK_S`.
