## Fit Score

- `scoring.compute_fit_score(fields)` produces a 0-100 int, appended as `_build_row()`'s last cell (the sheet's `ציון התאמה` column). Informational only — doesn't affect filtering, dedupe, or `dedupe_and_sort_sheet()`'s sort order (still newest-post-date-first).
- Six independently-weighted factors (`SCORE_WEIGHT_PRICE`/`SCORE_WEIGHT_LOCATION`/`SCORE_WEIGHT_ENTRY_DATE`/`SCORE_WEIGHT_AMENITIES`/`SCORE_WEIGHT_ROOMS`/`SCORE_WEIGHT_PARKING` in config.py, default 25/25/25/10/10/5, must sum to 100): price (cheaper within `[MIN_PRICE, SCORE_PRICE_SOFT_CEILING]` scores near-full, decays fast beyond it toward `MAX_PRICE`), location (walking distance floor at `MAX_WALKING_DISTANCE_KM`, plus a directional adjustment — north of `DESTINATION_LAT`/`LON` is a bonus, south/east a penalty, and a flat Givataim-over-Ramat-Gan bonus), entry date (below), floor/elevator condition + a shelter bonus, room count (3.0 full marks, decaying toward `MAX_ROOMS`), and parking (only private parking scores).
- **Entry-date scoring is rolling from *today*, not a fixed calendar date** (changed 2026-09-28, per user preference to move in ASAP): `scoring._entry_date_score()` resolves the field via `core.normalize.resolve_entry_date()` to a concrete date — `"מיידי"` resolves to today, `"DD/MM"` resolves to that day/month with the year inferred forward (rolls to next year if it already passed this year, the opposite of `_infer_post_date`'s backward-rolling for post dates) — then scores by real distance from today: full marks (1.0) on or before today, since moving in ASAP is always best and never penalized for being early; a Gaussian decay the later it gets (`SCORE_ENTRY_DATE_SIGMA_DAYS_AFTER`, default 25 days), tuned so December-or-later is already near 0. An unresolvable value (`resolve_entry_date` returns `None` — free text `_normalize_entry_date` couldn't canonicalize) scores a hard 0, same as missing.
- **`_normalize_entry_date()`** (`core/normalize.py`) canonicalizes the LLM's free-text `entry_date` to exactly `"מיידי"` or `"DD/MM"` before it reaches scoring/filtering (raw unrecognized text passes through unchanged — kept for display honesty, scores 0, never rejected). Priority order, a concrete date always wins over a vague phrase: (1) an embedded `D.M`/`D/M` anywhere in the text (not a full-string match, so `"החל מ-1.9"`/`"1.9 גמיש"` still resolve; on a range like `"1.9-15.9"` the leftmost/earliest date wins); (2) a Hebrew month-name mention (`_HEBREW_MONTH_NAMES`, includes common abbreviations) — a digit immediately before the name wins as the day, else a `תחילת`/`אמצע`/`סוף` (beginning/middle/end) qualifier maps to day 5/15/25, else bare month name defaults to day 15; (3) immediate/flexible phrasing (`_IMMEDIATE_RE`) → `"מיידי"` — deliberately includes `גמיש`/`בהקדם`/`מתי שתרצו`/`בתיאום`, since a landlord flexible on timing can accommodate moving in now, with a negative lookbehind so `"לא מיידי"` doesn't false-positive.
- **Far-out entry dates are hard-rejected, not just scored low** (`storage.VERDICT_REJECTED_ENTRY_DATE`, `core/evaluate.py`'s `_evaluate_post_data()`, right after `_normalize_entry_date`): if `resolve_entry_date()` confidently resolves to more than `SCORE_ENTRY_DATE_MAX_DAYS_AHEAD` (config.py, default 60) days from today, the listing never reaches the sheet. An unresolvable value is never rejected on this basis — same caution rule already applied to weak addresses. Applies automatically to `--replay`/`--reparse-rejected` (both route through `_evaluate_post_data`) and is in `get_reparse_candidates()`'s verdict list, so tightening/loosening the cutoff can be re-tested against stored raw text without re-scraping.
- **Agent-fee adjustment**: if `is_agent` is true, the *scoring* price (not the displayed price) is inflated by `price_val / AGENT_FEE_AMORTIZE_MONTHS` (default 12) — a one-time broker's commission (~one month's rent) amortized over a year of lease, so an agent listing competes against a private one on effective monthly cost rather than sticker price.
